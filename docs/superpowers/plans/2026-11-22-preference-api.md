# 취향 선택 API 연동 계획

**목표:** Swagger의 활동 조회 및 선택 제출 계약에 맞게 취향 선택 화면을 연동한다.

**구조:** 기존 HTTP 클라이언트와 TanStack Query를 사용한다. 활동은 서버 ID로 관리하고, 방 ID는 방 생성·참여 흐름에서 전달받는다. 방 생성과 로그인 연동은 다른 담당자의 작업이며, 해당 화면은 수정하지 않는다.

**기술:** Next.js, TypeScript, TanStack Query, Vitest.

**기준:** Swagger의 `GET /api/v1/activities`, `POST /api/v1/rooms/{roomId}/responses/me/submit` 및 대화에서 합의한 방 생성 후 제출 흐름.

## 작업

- [ ] API 응답과 요청 DTO 및 조회·제출 함수를 작성하고 성공과 오류를 테스트한다.
- [ ] 서버 활동 ID를 이용하도록 선택 상태와 카테고리 렌더링을 변경한다. 로딩, 빈 목록, 오류 및 재시도를 처리한다.
- [ ] 전달받은 방 ID와 인증을 사용해 선택 결과를 제출한다. 방 ID가 없거나 제출에 실패하면 성공 화면으로 이동하지 않는다.
- [ ] 기존 단계 전환, 선택 상태 유지와 뒤로 가기를 보존한다.
- [ ] 타입 검사, 린트, 테스트 및 빌드를 실행하고 실제 서버 검증의 한계를 기록한다.

## 확인 사항

- 방 생성·참여에서 취향 화면으로 방 ID를 전달하는 방식은 담당자 간 합의가 필요하다.
- 활동 목록이 비었거나 조회에 실패한 경우 기존 목데이터를 실제 데이터로 오인시키지 않는다.
- 제출 중 중복 요청을 막고 실패 시 선택한 내용을 유지한다.
- 인증 쿠키와 실제 서버 CORS는 배포 환경에서 검증한다.
